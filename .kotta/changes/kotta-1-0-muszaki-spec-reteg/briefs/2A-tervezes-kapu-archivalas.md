# 2A — tervezés-fázis, az emberi kapu, archiválás

Worktree: `../kotta-k1-plan`, ág `spike/k1-plan` (az 1. szakasz fejéről). Csak ott dolgozz; commitolj; ne pusholj. A `src/cli/index.ts`-ben csak a saját parancsaidat regisztráld.

Olvasd előbb: a change `proposal.md`, `specs/technical-model`, `specs/planning-phase`, `specs/narrative`, `specs/migration`, `design.md`, `tasks.md` 3. és 4.2; `README.md`, `templates/AGENTS.md`, `src/spec/registry.ts`, `src/commands/{validate,spec,questions,gap}.ts`, `src/core/{approval-receipt,questions,markdown}.ts`, a `tests/` mintái; és `briefs/README.md` közös szerződéseit.

## Feladat

1. **Provenance minden node-on** a README szerinti sémával: a regiszter közös frontmatter-szabályai közé, a JSON-sémába, a `templates/`-be; `kotta spec new` vázlatolja; `kotta validate` ellenőrzi, ha jelen van, és megköveteli a change `model/` alatt.
2. **Change-elrendezés** a README szerint; `kotta spec new --into <change>` a change `model/`-jébe mintáz.
3. **`kotta plan <change>`** — a tervezés gépi fele (a fordítást ágens végzi a 6. pont skilljével). Beolvassa a delta `model/`-t és az elfogadott `.kotta/spec/`-et, és `planning.md`-t ír: (a) a delta szerkezeti validálása (fejezetek, kötelező élek, id-k, provenance); (b) az összefésült nézet (elfogadott + delta) validálása egészben; (c) **ütközések**: gépi jelöltek — közös entitás/subject él egy módosított node-dal, egy módosított node által hivatkozott node-ok, glossary „nem ez” kontraszt az új címekre, törölt vagy megfordított állapotgép-átmenet — rangsorolva, változásonként legfeljebb 10, ítéletre váró jelöltként jelölve; (d) **hallgatások**: a formák megválaszolatlan kérdései (`core/questions.ts`, `## Open decisions`); (e) **eltérés**: a narratív spec (`openspec/changes/<név>/specs/**`, `openspec/specs/**`) `<!-- kotta: ID -->`-vel kötött követelményei, amelyek SHALL-mondata a node óta változott — jelentés, nem javítás; (f) provenance-összesítés: hány kimondott/következtetett, ki döntött, a gép döntéseinek listája. Nem nulla kilépés, ha (a) vagy (b) bukik vagy van nyitott döntés. `--json`.
4. **`kotta approve <change> --by <ki>`** — az egyetlen emberi kapu. Elutasít pontos listával, ha a `planning.md` régebbi bármelyik model-fájlnál, ha van nyitott döntés, ha a szerkezet nem valid. Sikerkor `approval.yaml` a `core/approval-receipt.ts`-szel (ki, mikor, alap = a delta hash-e), és címmel írja ki, mit hagyott jóvá. Az ember a chatben mond igent; a parancs csak rögzíti.
5. **`kotta archive <change>`** — érvényes, aktuális `approval.yaml` nélkül (hash egyezik) elutasít. Utána: beolvasztja a `model/`-t a `.kotta/spec/`-be (új node hozzáadva, azonos id cserélve, REMOVED törölve — ha elfogadott node még hivatkozik rá, elutasít); újragenerálja az érintett képességek narratíváját `capability:` szerint `openspec/specs/<capability>/spec.md`-be OpenSpec-formában (`## Purpose` a képességre mutató cél-node-ból vagy megtartva; `### Requirement:` szabályonként/interfészenként/minőségi jellemzőnként/use case-enként/storynként; `#### Scenario:` a `subjects` szerint bizonyító példákból; minden fejléc után `<!-- kotta: ID -->`; a próza a node saját szakaszaiból, kitalált szöveg nélkül), és lefuttatja az eltérés-ellenőrzést, hogy a generált próza egyezik a modellel. A change-et `openspec/changes/archive/<dátum>-<név>/` alá mozgatja. A modell az elfogadott igazság; az eltérést jelezni kell, sosem csendben feloldani.
6. **`plan-change` skill** a `skills/` alatt (`kotta sync` telepíti): a tervezés ágens-oldala — hogyan fordítja a change proposal/specs (és a `conversation.md`) tartalmát `model/` node-okká provenance-szel; „soha ne találj ki szándékot: nyitott döntést rögzíts”; a miértet előbb a narratívában keresd; `kotta plan` futtatása; mit vigyél a chatbe a kapuhoz (címek, kérdések, a gép döntéseinek listája). A `templates/AGENTS.md`-be röviden a négy réteg és ez a munkamenet.
7. **Tesztek** (vitest): regiszter elfogad/elutasít provenance-t; `spec new --into`; `plan` egy fixture change-en egy ütközéssel, egy hallgatással, egy eltéréssel → jelentés-tartalom és kilépési kód; `approve` elutasításai és nyugtája; `archive` beolvasztás + REMOVED-elutasítás + prózagenerálás egyezik a modellel + a change átmozgatva. Fixture: 3–5 node-os elfogadott spec + egy change `model/`-lel. `npm run typecheck`, `npm test`, `npm run build` zöld.

Minden tisztázatlan pont a change `DECISIONS.md`-jébe (egy bullet). Zárójelentés magyarul, tömören: parancsok és opciók, a provenance-séma ahogy megvalósult, mikor utasít el a plan/approve/archive, tesztszámok, typecheck/build, commitok, DECISIONS-bejegyzések.
