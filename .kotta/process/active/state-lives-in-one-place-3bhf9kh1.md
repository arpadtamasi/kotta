## Outcome

Entity lifecycle state is stored once. `process/tasks/`, `process/batches/` and
`process/observations/` hold one stable file per entity; `status:` frontmatter is the single
authority; every transition is an in-place edit. The duplication class born from
directory-as-state — dedupe, DUPLICATE_STATE, the T-036 merge damage — ceases to exist.

## Current structural problem

State is encoded twice: in `status:` and in which of eleven state directories the file sits.
Every reader trusts the directory (the board overwrites frontmatter from it); fifteen transition
functions move files; a Git merge of two transitions leaves one entity in two directories.

## Demonstrated cost or risk

The dedupe command, the index merge=union attribute, the DUPLICATE_STATE error class, a 222-line
test suite for merge damage, and git-version-sensitive fixtures all exist only to manage the dual
encoding. D-003 deferred exactly this fix; F-008 named it as a root cause.

## Behavioural invariants

- Every CLI command keeps its name, arguments, human output shape, --json fields and exit codes,
  except `task dedupe` and `batch dedupe`, which are removed with the failure mode they served.
- The board's wire format is unchanged: entities arrive with a status string; filters and labels
  behave identically.
- All lifecycle rules, gates, receipts, coverage checks and claims behave identically.
- Identifiers never change; `git log --follow` reaches a migrated file's history.

## Target structural property

One directory per entity kind; state read from frontmatter everywhere; one shared state-vocabulary
module (the board stops re-declaring it); transitions writable as tmp+rename in-place edits;
workspace shape version 5 with a migrate step, the compatibility window moving to v4.

## Excluded redesign

No change to the event store, claims, decisions, profiles or spec namespace layout. No change to
gates or approval semantics. No new commands beyond the migrate step. index.md stays where it is
with its union merge rule, regenerated by frontmatter status.

## Behaviour-preserving verification

The full vitest suite passes with path assertions updated to the flat layout and no assertion
weakened; the site and UI suites pass unchanged in substance; a v4 fixture migrates to v5 with the
id set proven equal; a v4 fixture with duplicated state is refused with both paths named.

## Scope

1. Flatten the state mapping in src/filesystem (entities, batches, workspace) and all readers.
2. Convert the fifteen movers to in-place writers; remove dedupe and DUPLICATE_STATE.
3. Rewrite regenerateIndex to group by frontmatter status.
4. Board: shared state vocabulary, one-directory gather, frontmatter status, App.tsx path fix.
5. migrate: v5 flatten step with per-file collision refusal, status transcription from the source
   directory, ID_DIRECTORIES extension; version constants and config schema to 5; compat window
   to v4.
6. Update tests, templates, skills text, README layout diagram and site hero path; migrate this
   repository's own workspace in the same change; changelog Breaking entry.

## Non-goals

Machine-checkable evidence (the next wave). Event-store, claim or profile changes. Any behavioural
change to gates. Multi-version migration ladders — migrate remains "any supported old shape to
current".

## Acceptance

- Every entity lives in one stable file with lifecycle state in the frontmatter status field alone, and every transition is an in-place edit, never a move.
- A conflicting transition surfaces as an ordinary merge conflict on the status line, and an identifier collision inside an entity directory is reported by validation; the two-state-directories failure mode and its dedupe recovery no longer exist.
- kotta migrate carries a version-4 workspace to the flat version-5 shape with the identifier set proven unchanged, and refuses a workspace whose duplicated state cannot be flattened safely.

## Verification

- npm test, npm run typecheck, npm run test:site all green.
- New migrate fixtures: clean v4 → flat v5 (id set equal, statuses transcribed); duplicated-state
  v4 → refused naming both copies.
- A full task lifecycle exercised on the migrated workspace with git status confirming in-place
  edits only.
- grep proves no state-directory path remains in src/ outside the migrate reader.

## Constraints

- One-version compatibility window: v3 reading is removed with the move to v5.
- The tmp+rename atomic write pattern is kept for in-place edits.
- The refactor profile's excluded-redesign list is binding.

None.
