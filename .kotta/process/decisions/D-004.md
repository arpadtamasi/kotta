# D-004 — Task/goal operational model — two gates, two readies, goal/run split, open-question as decision-request

## Decision

Consolidates the task/goal operations worked out from intent (continuation of D-001/002/003).

- **Two human gates bracket the machine.** `backlog → ready` (the contract is complete) and `review → done` (accept the evidence). The machine owns `ready → active → review` between them, ungated. `ready` is the in-gate to autonomy; `done` the out-gate.

- **"Ready" is two different checks.**
  - **Intrinsic-ready** — the contract is self-complete: judgment removed, testable acceptance, bounded scope, `Open decisions: None`. A property of the task alone; **stable**; human-approved (`require_human_ready_approval` — the validator checks form, the human checks quality).
  - **Pre-flight / launch-ready** — safe to fire *now* into the current world: no conflict with in-flight work, not already-done/redundant, blast-radius understood, prerequisites actually merged. A property of the task relative to everything else; **volatile** (decays as other work lands); checked at the last moment before dispatch; largely **computable**, so an agent can gather it (F-007 pattern, at the launch moment). This is the collision-control counterpart to D-003's identity-collision fix: D-003 = identity can't collide; pre-flight = work shouldn't collide.

- **"Package" splits into goal + run.**
  - **Goal** — durable outcome. Carries a **measurable success-definition**, accumulates findings (the cluster — an "attach-existing" home), spins off tasks, and **outlives its tasks**.
  - **Run** — ephemeral launch: which tasks this time + execution (mode / parallelism / stop_on_failure). Execution settings belong to the run, not the goal.

- **The goal needs a second gate the model lacks: assess.** A task's `review → done` (accept evidence) has no goal-side pair. A goal is not achieved because its tasks are done (a checklist) but because the **outcome moved** (a measurement). `task: review → done` ↔ `goal: active → assessed`.

- **Open questions are decision-requests — the pull-sibling of the push-finding.** A finding is "I saw something" (observation → disposition); an open question is "I cannot proceed without your call" (gap → decision). They surface at three moments — shaping, pre-flight, and mid-execution (the agent must stop and ask, never silently decide) — **block** readiness, and resolve into a decision (D-xxx) or must **park somewhere real** (not a ticket body, where they evaporate). **OPEN / undecided:** whether an open question is a first-class entity with its own lifecycle, or lives inside the task/goal and only needs a durable parking home.

## Context

The operator supplied the full domain intent; the goal is that **the tool AND the UI support this way of working**. The pressing driver: real work is progressing in the one&a workspace and is currently **not overviewable** — today even task details are not visible (F-005). This model is the payload for the detail views and for the roadmap.

## Consequences

- **Detail views (F-005) must render, per entity:**
  - *finding* — channel tag + addressability, evidence, dup/related context (F-007), proposed disposition + justification, the two closures (dispositioned / delivered-on-task-verify).
  - *task* — the contract, intrinsic-ready status, pre-flight status, claim/branch/worktree provenance (F-006), open questions raised, at review the acceptance↔evidence + deviations + residue, and both gates.
  - *goal* — measurable success-definition, accumulated findings, member tasks with status, a run-launcher with pre-flight summary, and assess status.
- **Critical path to a transparent one&a:** T-016 (truth-from-derivation fix) first — the overview must be *true* before it is *detailed* — then the detail views; and the corrupted one&a state (F-008 collisions/dups) must be cleaned or the overview shows garbage.
- Still open (deferred / undecided): open-question as entity vs. in-entity + parking home; assess-gate mechanics; the goal/run schema split; the `signal/ticket → task → goal` naming.
