# D-003 — Entity identity is a coordination-free ULID; humans reference by title; D-001 stays read-only

## Decision

Separate the two jobs a sequential id conflates and does both badly: machine identity and human reference.

- **Machine identity = a coordination-free, time-sortable id (ULID / KSUID).** 128-bit, timestamp-prefixed, so it is lexicographically sortable (ordering is preserved) AND collision-free with **no allocator, lock, or base-ref coordination**. Two agents on two branches mint distinct ids independently; a cross-branch collision (as with F-008 / T-049) becomes impossible. The race is not won — it is removed.

- **Human reference = the title / slug.** Links (`depends_on`, `blocks`, package membership, `source_finding`) target the **stable id**; the title is display only — it is mutable and may duplicate, so it is **never** a link target. Show a short id tail (e.g. `title · a3f9`) only to disambiguate.

- **Filename = slug + short id suffix** — readable, and disk-unique even across branches.

- Supersedes the base-ref id-allocation idea floated while discussing D-001: identity minting needs no coordination. **D-001 remains valid but is scoped to read stability** (where state is read from), not to identity.

## Context

Live evidence from the one&a workspace (2026-07-26): concurrent agent worktrees + merges produced real id collisions (F-008, T-049 — two distinct entities each) and merge-duplicated states (T-039/040/041, P-015). The sequential `nextId()` (scan max+1) cannot coordinate across branches, and the earlier atomic-reservation fix (T-011) covered only decisions. Separately, sequential ids are a poor human reference — "T-049" carries no meaning — which pushes reference toward titles anyway.

Captured as its own bug finding with the full evidence.

## Consequences

- **Identity migration is real**: every `T-`/`F-`/`P-` reference (prose, commits, `depends_on`, package membership, index, `source_finding`) moves to id + title. Non-trivial; sequence carefully.
- Fixes the **id-collision** root, but **not** the directory-as-state merge duplication (T-039/040/041, P-015) — that is a separate root (git merge does not treat a cross-directory move as delete+add) and needs its own fix (merge-aware state, or state-in-frontmatter). Tracked in the sibling finding.
- Enables safe concurrent worktrees/agents (the model being built) without an allocation lock on the id path — narrows the scope of the T-002 mutation lock.
- Reference-by-title connects to the deferred `signal/ticket -> task -> goal` naming: if humans reference by title, the entity *type* words matter more than the numbers.
