# D-005 — Product name — Kotta (working name, replacing A-Team); "ready" is displayed as "defined"

## Decision

**The product is called Kotta.** Hungarian for *musical score*. Adopted as a working name — good enough to build under, not yet locked as a brand.

**Ticket state `ready` is displayed as `defined`.** The stored status value stays `ready` everywhere (schema, filesystem, CLI, API); only the human-facing label changed, via a `stateLabel()` map in the UI. The full rename is deferred — it touches ~31 files plus a workspace migration.

## Context

`A-Team` names nothing about the product. It recalls a TV series, is unsearchable, and says nothing about the thesis.

The naming search converged only after the operator corrected the framing twice:

1. **The product's asset is the ticket corpus, not the code** (see F-017). If findings caused by an earlier ticket's under-specification are written back into that ticket, the corpus stays a complete, current specification — and the app can be regenerated from it in one pass, on a newer stack or a newer model. The code becomes disposable; the tickets become the asset. That is the anti-legacy claim.

2. **The plan is an output, not an input** (see F-015). You whittle the plan: model, prototype, discover — and the plan exists at the *end*. This killed the whole first family of candidates (`Keel`, `Plumb`, `Datum`, `Truss`), all of which imply a solid foundation laid down before you build.

**Kotta carries both directions.** You play first, then write it down — the score is the residue of the performance, not the instruction before it (that is the whittling). And once written, anyone can play it again, indefinitely — that is the regeneration. One word holds F-015 and F-017 together.

Practical checks at the time of the decision:

- `kotta.dev`, `kotta.sh` and npm `kotta` were all unregistered; `kotta.com` was taken.
- Two syllables, no diacritics — an English reader pronounces it correctly on sight and spells it correctly on hearing. It does not read as a foreign word.
- Not a common English noun, so the product is searchable on its own name. Every short English candidate tested (`score`, `keel`, `plumb`, `datum`, `warp`, `kiln`, `truss`) was registered on `.dev` and `.sh`.
- `recast` was rejected late: the npm package of that name is the JavaScript AST transformer, ~33M downloads/week, in exactly this product's audience.

The one-line story: *Kotta is the Hungarian word for a musical score. You play first — then you write it down, and anyone can play it again.*

## Consequences

- The rename is a ticket, not an edit: npm package name, CLI binary, `.a-team/` directory name, skills, templates, schemas, docs, site. Needs a migration path for existing workspaces.
- `defined` vs the `tickets/ready/` path and `POST /api/ticket/ready` now visibly disagree in the UI. Left deliberately — the gap shows the size of the remaining rename.
- Open, and connected: D-004 still parks the `signal/ticket → task → goal` naming. That vocabulary and this rename should land together, not in two passes.
- Working name, not locked. Revisit before any public launch or trademark step.
