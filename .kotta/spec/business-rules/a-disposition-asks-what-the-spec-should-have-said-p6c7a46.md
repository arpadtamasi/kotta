## Rule

Before an observation is dispositioned, one question decides which exit it takes: what would the accepted specification have to say for this not to happen again? Where the remedy adds behaviour no node states - a new capability, a new obligation, a new refusal - the answer is that sentence, the disposition is amend-spec, and the work follows from the landed delta. Only where the remedy adds nothing the specification does not already promise, because the promise is complete and the code simply failed it, is a plain task the right exit; that is the case which must be argued, not assumed. Noticing something outside the scope of the task in hand says nothing about the agreement either way: an observation defers, and the question is asked when it is dispositioned.

## Rationale

A repository accumulates fixes; a score accumulates promises. Dispositioning by "is there already a rule about this area" answers the wrong question and lands the remedy silently: the capability ships, no node states it, and the next reader has behaviour with no agreement behind it - the same unspecified enforcement the gap report exists to surface, created deliberately. Asking what the specification should have said turns each noticing into a candidate amendment, so the agreement grows where the work actually revealed it to be thin, rather than only where someone thought to write it in advance.

## Scope

Every observation reaching a disposition, on any surface. The rule governs which exit is chosen and what has to be true to choose it; the exits themselves, their approval and their receipts are unchanged. It does not make every defect an amendment: a complete promise failed by its implementation stays a defect.
