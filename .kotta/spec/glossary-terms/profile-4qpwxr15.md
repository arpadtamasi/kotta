## Definition

A type-specific requirement set a task opts into - bug, ui, performance, metric, workflow, refactor, discovery - shipped as YAML under the process namespace.

## Usage

A profile adds required definition sections (a bug task must state reproduction and expected behaviour, a ui task its states) and done-checks that join the acceptance conditions in the review evidence. A task's profiles travel into its brief.

## Non-examples

A task type. A template that fills itself in - the profile demands the sections, the author answers them. A gate of its own.
